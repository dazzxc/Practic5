# Движок проверок качества данных

Проверяет CSV, Excel (.xlsx) и JSON любого размера. Файл читается кусками,
поэтому целиком в память не грузится. Всё написано на pandas, без pandera.

## Установка
```
pip install -r requirements.txt
```

## Запуск из консоли
```
python run.py                       # тестовый clients.csv
python run.py мой_файл.csv          # свой файл (.csv, .xlsx, .json, .jsonl)
python run.py мой_файл.csv 50000    # свой размер куска (по умолчанию 15 000 строк)
```

## Тесты
```
pytest
```

## Тестовые файлы
```
python make_demo_files.py              # небольшие файлы для показа
python make_big_file.py 1000000        # test_data/big.csv на 1 млн строк
python make_big_file.py 200000 xlsx    # test_data/big.xlsx
python make_big_file.py 500000 json    # test_data/big.json
```

Демо-файлы в `test_data/`:
- `demo_orders.xlsx` - заказы магазина, 502 строки;
- `demo_employees.json` - сотрудники с вложенным адресом, 301 запись;
- `demo_transactions_1c.csv` - как выгрузка из 1С (`;`, Windows-1251, русские колонки, запятая в дробях), 402 строки;
- `demo_clean.csv` - чистый файл, ошибок там быть не должно.

В первых трёх есть ошибки всех 4 групп. Большие файлы в git не попадают.

## Что где лежит
```
checks/
  __init__.py     - check_file() и run_all_checks(), с них всё начинается
  reader.py       - чтение CSV и Excel кусками (кодировку и разделитель угадывает сам)
  json_reader.py  - чтение JSON кусками
  auto_rules.py   - подбор правил под любой файл
  issue.py        - формат одной ошибки и общие помощники
  missing.py      - 1. пропуски
  duplicates.py   - 2. дубликаты
  invalid.py      - 3. некорректные значения
  consistency.py  - 4. несогласованности
tests/             - тесты
test_data/         - тестовые файлы
run.py             - запуск из консоли
make_demo_files.py - демо-файлы
make_big_file.py   - большой файл для проверки скорости
```

## Как вызвать из кода
```python
from checks import check_file

result = check_file("файл.csv")            # правила подберутся сами
result = check_file("файл.csv", config)    # или свои
# result: total_rows, columns, issues, summary, config, auto_rules
```
Можно передать `on_progress=функция`, она будет получать число проверенных строк
после каждого куска (для прогресс-бара).

## Как подбираются правила
Если `config` не передать, смотрим на первый кусок файла (`checks/auto_rules.py`):
- **email**: в названии email/mail/почта или в значениях есть `@`;
- **число**: 80%+ значений числа, остальное - ошибка. Возраст 0..120, цены, суммы и количество не меньше 0;
- **дата**: 80%+ значений подходят под обычный формат (`2026-01-31`, `31.01.2026` и т.п.);
- **ключ**: колонка вида `id`, `*_id`, `*ID`, где значения почти не повторяются - ищем повторы;
- **список**: для пола М/Ж и похожие варианты; в других колонках с 2-10 значениями редкие (<0,5%) считаем опечатками;
- **пары дат**: start/end, created/completed, order/delivery и т.п. - конец не раньше начала;
- **итог**: если есть цена, количество и итог, итог должен сходиться.

Какие правила сработали, видно в `result["config"]`.

## Группы ошибок
У каждой ошибки есть `category` - одна из 4 групп, а в `type` - подробнее:

| category | type |
|---|---|
| `missing` | `missing` |
| `duplicate` | `duplicate_row`, `duplicate_key` |
| `invalid` | `wrong_type`, `out_of_range`, `wrong_format`, `wrong_date`, `not_allowed` |
| `inconsistency` | `inconsistent` |

`result["summary"]` - сколько ошибок в каждой группе.

## Какой JSON понимаем
- список объектов: `[{"id": 1}, {"id": 2}]`
- JSON Lines, по объекту на строку
- обёртку вида `{"data": [...]}` - ключ найдём сами
- вложенные объекты становятся колонками через точку: `address.city`
- если поле есть не у всех записей, у остальных это пропуск

## Ограничения
- Старый `.xls` не читаем, его надо пересохранить в `.xlsx`.
- Excel читается раз в 10 медленнее CSV.
- Для поиска дублей храним 8 байт на строку: 100 млн строк - примерно 800 МБ.
