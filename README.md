========================================================================
СЕРВИС АУДИТА КАЧЕСТВА ДАННЫХ (DATA QUALITY ASSESSMENT SERVICE)
ПОЛНОЕ РУКОВОДСТВО И ДОКУМЕНТАЦИЯ ПО ПРОТОТИПУ
========================================================================

Данный инструмент предназначен для автоматического анализа табличных данных
(формат CSV) на наличие логических ошибок, пропусков, дубликатов и 
аномальных значений перед их отправкой в аналитические хранилища.

------------------------------------------------------------------------
1. КАК РАБОТАЕТ ПРОГРАММА (АРХИТЕКТУРА И ЛОГИКА КОНВЕЙЕРА)
------------------------------------------------------------------------
Прототип разбит на независимые модули, что соответствует ролям в команде:

1. Схемы данных (schemas.py) — контракт системы. Описывает, из каких полей 
   состоит отчет об ошибках, используя библиотеку Pydantic. Гарантирует, 
   что данные всегда будут в строгом и валидном формате.
   
2. Компонент загрузки (data_loader.py) — принимает файлы и переводит их 
   в удобный для Python табличный формат (Pandas DataFrame).

3. Движок валидации (quality_engine.py) — "сердце" системы. Он сканирует 
   таблицу по универсальным алгоритмам:
   - Ищет пустые ячейки (Null/NaN) по всем колонкам.
   - Ищет полные дубликаты строк.
   - Рассчитывает метрики комплектности данных (Completeness Score) 
     и общий индекс качества (Quality Score).
   - Вытаскивает "сэмплы" (примеры) ошибочных строк.

4. Генератор отчетов (report_gen.py) — сохраняет результаты работы движка.
   Выдает технический лог (dq_report.json) для фронтендеров и наглядный 
   бизнес-отчет (dq_report.xlsx) для аналитиков.

5. Точка входа (main.py) — интерактивная консоль. Запрашивает у пользователя 
   путь к любому CSV-файлу, запускает конвейер и выводит статус в терминал.

------------------------------------------------------------------------
2. ИНСТРУКЦИЯ ПО РАБОТЕ С ТЕСТОВЫМИ ДАННЫМИ (ГЕНЕРАТОР БОЛЬШИХ ФАЙЛОВ)
------------------------------------------------------------------------
В проекте реализован динамический генератор синтетических данных 
(test-files-generator.py). Он создает эталонные "грязные" файлы для 
проверки устойчивости движка.

Для корректного открытия создаваемых CSV-файлов в Excel/WPS Office без 
сдвига колонок и нарушения кодировки, в генераторе принудительно 
используются параметры:
- Разделитель: точка с запятой (sep=";")
- Кодировка: UTF-8 с сигнатурой (encoding="utf-8-sig")

Чтобы сгенерировать файлы заново, выполните команду (см. Раздел 3):
python test-files-generator.py

Скрипт создаст:
- large_users_quality.csv (10 000 строк с пропусками ФИО и аномалиями возраста)
- large_transactions_quality.csv (50 500 строк со скрытыми дубликатами и ошибками дат)

------------------------------------------------------------------------
3. ПОШАГОВАЯ ИНСТРУКЦИЯ ПО РАЗВЕРТЫВАНИЮ И ЛОКАЛЬНОМУ ЗАПУСКУ
------------------------------------------------------------------------
Ввиду того, что политики безопасности Windows (Execution Policies) могут 
блокировать стандартную активацию виртуальных окружений в PowerShell, 
рекомендуется использовать самый надежный способ установки — через 
глобальный интерпретатор Python.

Выполните в терминале из КОРНЯ проекта (папка Practic5) по очереди:

ШАГ 1: Установка необходимых библиотек (Pandas, Pydantic, OpenPyXL)
   python -m pip install pandas numpy openpyxl sqlalchemy pydantic

ШАГ 2: Генерация демонстрационных файлов (если их нет на диске)
   python test-files-generator.py

ШАГ 3: Запуск основного прототипа движка валидации
   python -m prototype.main

ШАГ 4: Тестирование системы
   Когда программа выведет запрос: "Введите путь к вашему CSV-файлу", 
   введите имя одного из сгенерированных файлов, например:
   large_users_quality.csv

------------------------------------------------------------------------
4. РЕЗУЛЬТАТ РАБОТЫ ПРОГРАММЫ
------------------------------------------------------------------------
После завершения анализа в корне проекта обновятся файлы:
- dq_report.json — структурированные данные инцидентов.
- dq_report.xlsx — красивый Excel-отчет со сводными метриками.

------------------------------------------------------------------------
ОСОБЕННОСТИ ФОРМИРОВАНИЯ МЕТРИК В ФАЙЛЕ TRANSACTIONS:
------------------------------------------------------------------------
При анализе файла `large_transactions_quality.csv` в колонке `amount` 
можно заметить вещественные числа с длинным "хвостом" знаков после запятой 
(например, 65748.5031...). 

Это является УМЫШЛЕННОЙ архитектурной особенностью генератора:
1. Симуляция сырых логов: В реальных финансовых системах при конвертации 
   валют или расчете дробных долей (например, в криптотранзакциях или 
   сложных скидках) данные хранятся с максимальной точностью (float/double).
2. Стресс-тест движка: Длинные дробные хвосты позволяют проверить, как 
   наш Quality Engine и библиотека Pandas справляются с типами данных 
   высокой точности и не округляют ли они их автоматически при расчете 
   интегрального индекса качества.
