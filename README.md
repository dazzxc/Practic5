# Прототип сервиса аудита качества данных (Data Quality Tool)

## 1. Суть проекта

Представьте, что крупная компания (например, банк или интернет-магазин) каждый день собирает терабайты данных: списки клиентов, отчеты о продажах, даты транзакций. Эти данные загружаются в систему из разных мест.
Очень часто эти данные поступают «грязными»:
*   Менеджер забыл ввести возраст клиента (в таблице появляется пропуск).
*   Система из-за сбоя записала одного и того же человека дважды (дубликат).
*   В поле «сумма» случайно указали отрицательное значение (некорректное значение).
*   Дата завершения транзакции стоит раньше, чем дата её создания (несогласованность).
Если анализировать или обучать нейросети на таких «грязных» данных, бизнес понесет огромные убытки. Наш прототип создан для автоматического поиска таких аномалий.

## 2. Как устроен наш прототип

Мы разбили код на несколько модулей, чтобы каждый человек в команде отвечал за свой понятный кусочек. Вот как данные идут по конвейеру:

1.  **Загрузчик (`data_loader.py`)** — «Приемщик товара». Его задача — взять файл (CSV) или залезть в базу данных и превратить это в понятную для Python таблицу (DataFrame). Он умеет автоматически определять кодировку и разделитель (`;` или `,`).
2.  **Контракты данных (`schemas.py`)** — «Шаблон-инспектор». Здесь мы используем библиотеку Pydantic. Это строгие правила, которые описывают, в каком виде отчет об ошибках должен быть передан дальше. Она гарантирует, что бэкенд и фронтенд будут говорить на одном языке.
3.  **Движок проверок (`quality_engine.py`)** — «Сердце системы». Это главный робот. Он сканирует таблицу и находит 4 типа проблем (о них ниже).
4.  **Генератор отчетов (`report_gen.py`)** — «Секретарь-оформитель». Он берет найденные ошибки и превращает их в два документа: `json` (для программистов) и `xlsx` (красивый Excel для аналитиков).
5.  **Графический интерфейс (`gui.py`)** — «Пульт управления». Современное десктопное приложение на PyQt6. Позволяет выбрать файл в пару кликов, посмотреть красивый дашборд с метриками и таблицу с подсветкой ошибок, а затем экспортировать отчеты.

## 3. Какие проверки мы реализовали

Наш движок (Core QA Engine) умеет находить следующие аномалии:

*   **Пропуски (`missing_values`):** Ищет пустые ячейки (NaN) в любой колонке. *Умная логика:* если пропусков больше 20% от общего числа строк, ошибке присваивается статус `high` (критическая), иначе `medium`.
*   **Дубликаты (`duplicates`):** Находит полные дубликаты строк (когда все значения в строке повторяются). Статус всегда `high`.
*   **Несогласованность дат (`date_inconsistency`):** Проверяет логику времени. Если дата завершения (`completed_at`) меньше даты создания (`created_at`), программа фиксирует нарушение.
*   **Некорректные значения (`invalid_value`):** Проверяет числовые колонки (например, `amount`). Отрицательные суммы или аномальные текстовые значения помечаются как критическая ошибка.

## 4. Метрики качества (Quality Metrics)

После завершения проверки система считает две главные метрики:
1.  **Completeness (Полнота):** Показывает процент заполненных ячеек. Вычисляется как `(Общее число ячеек - Пропуски) / Общее число ячеек * 100%`.
2.  **Quality Score (Индекс качества):** Интегральная оценка от 0 до 100. Мы начинаем со 100 баллов и вычитаем штрафы за каждую найденную проблему в зависимости от её критичности:
    *   `high` (критическая) — минус 10 баллов.
    *   `medium` (средняя) — минус 5 баллов.
    *   `low` (низкая) — минус 2 балла.

## 5. Зачем мы выбрали именно этот стек технологий?

*   **Python** — мировой стандарт для работы с данными и аналитики.
*   **Pandas** — самая мощная библиотека для работы с таблицами. Умеет перемалывать миллионы строк за доли секунды.
*   **Pydantic** — защищает программу от ошибок. Если мы ждем на входе число, а пришла строка, Pydantic сразу это поймает.
*   **SQLAlchemy** — мост между Python и базами данных (в будущем).
*   **PyQt6** — современный фреймворк для создания кроссплатформенных десктопных приложений. Мы выбрали его для быстрого и красивого прототипа (MVP).

## 6. Планы по развитию (Roadmap для защиты)

Текущая версия — это полностью работающий Desktop-прототип. Архитектура спроектирована с учетом масштабирования на Web:
1.  Ядро (`quality_engine.py`) уже отдает данные в формате JSON (Pydantic).
2.  Следующий шаг — обернуть движок в **FastAPI** (создать эндпоинты `/upload`, `/run-check`).
3.  После этого Desktop-клиент PyQt6 можно будет заменить на **React**-приложение (дашборд с графиками Recharts), которое будет общаться с Python-бэкендом по REST API.
4.  Для очень больших файлов (терабайты) мы заложили возможность подключения **Celery + Redis** для фоновой обработки без блокировки интерфейса.
